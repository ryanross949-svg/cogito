Project Overview
Cogito is a collection of interactive, Brilliant-style cognitive training simulators. Built entirely in pure HTML/CSS/JS. No backend. Progress saves locally to the browser via localStorage.

Architecture & File Structure
index.html: The Master Hub. Reads localStorage from all apps to display Global XP, Global Radar Chart, Robust Operator Profile, and houses the global Theme Switcher.
prima.html: First Principles / Elon Musk (Engineering) - v7.0 (Master Template)
nash.html: Game Theory / MIT 14.12 (Strategy) - v7.0 (Master Template)
oracle.html: AI Prompt Engineering & Agents (AI) - v7.6 (Master Template)
How to Build a New App
Copy oracle.html (it is the most stable, fully-featured template).
Update the STORAGE_KEY variable (e.g., fermi-v1).
Update the MODULES array (10 axes).
Update the CARDS array (120 flashcards, 12 per module).
Update the ARENA array (100 problems, 10 per module, 4 difficulty tiers).
Update the PROJECT_PHASES array (10 cumulative project phases).
Update the REAL_WORLD_MISSIONS array (30 daily missions).
Add the new app to the APPS array in index.html so it tracks on the Global Dashboard. Its `domain` MUST be one of the 7 master discipline keys in the DISCIPLINES array: physics, math, compute, life, mind, strategy, systems. The Global Mastery Matrix (radar) and Discipline Breakdown aggregate every course up to these 7 axes (average maturity per discipline; XP summed). An unknown domain is now skipped gracefully instead of crashing the hub, but the course won't appear until its domain matches a discipline.
Link the shared stylesheet instead of copying CSS: <link rel="stylesheet" href="cogito.css"> in <head>, then one <style>:root{...}</style> after it holding only that course's palette. Copy the Theme Switcher HTML and JS from ORACLE v7.6; its CSS already lives in cogito.css.
Styling
cogito.css is the single stylesheet for all 52 course pages. It holds every shared rule plus all 8 theme definitions. Do NOT paste CSS into a course page. Before this file existed there were 32 divergent copies of the same stylesheet, and three themes (plain, crimson, emerald) had been added to index.html only, so selecting them did nothing on any course page.
A course page overrides exactly one thing: its own :root palette. Everything else is inherited.
Colour tokens are named for their ROLE, never their appearance: --accent / --accent-dim (the course's primary colour), --accent-2 (secondary), --success (correct, completed, read), --warn (caution, mid mastery, difficulty 2), --danger (wrong, low mastery). Structural tokens are --void / --void-2 / --panel / --panel-solid / --text / --text-dim / --text-faint / --border / --border-bright / --display / --mono.
Never reintroduce appearance-based names. The tokens were once called --cyan, --magenta, --green and so on, which broke down immediately: --cyan held green on lakoff and --magenta held purple on godel, so the CSS could no longer be read and trusted. A name must survive a re-theme.
index.html and review.html still carry their own inline CSS; they are different surfaces and were deliberately left out of the extraction.
Key Mechanics
Spaced Repetition (SM-2): Flashcards schedule based on quality (1-5). Maturity is 21+ days.
Progression: A module is marked "complete" when the Lesson is read AND 1 Arena problem is solved. This unlocks the next module.
Arena Difficulties: 1 (Easy, 50 XP), 2 (Medium, 100 XP), 3 (Hard, 200 XP), 4 (Expert, 500 XP). Distractors must be plausible MBA/engineering advice.
Leveling: Math.floor(Math.sqrt(xp/100)) + 1.
Global Hub: index.html parses the JSON of all app save keys to sum Total XP, average Maturity, and generate a Radar Chart + Profile based on balance.
Strict Project Gating: Project Phase N only unlocks if Module N is unlocked AND Project Phase N-1 is solved.
Themes: 8 themes (Quantum, Plain, Light, Nord, Matrix, Cyberpunk, Crimson, Emerald) via data-theme on <body> + localStorage cogito-theme. Defined in the THEMES array in index.html and unlock-gated: Quantum and Plain (an easy-readability theme) are free from the start; the rest unlock by global level (capped at 75) or a non-level condition (e.g. Emerald = 30-day streak). renderThemeMenu() builds the dropdown with lock states; setTheme() refuses locked themes; the saved theme is reapplied on load.
Background Shop: 16 canvas skins live in cogito-bg.js (shared by the hub AND all 50 course pages via a <script src="cogito-bg.js"> include + initBackground()). The shop (BACKGROUNDS array in index.html) gates each skin by level (capped at 75) or a check()/req — Sonar = 30-day streak, Singularity = master all 7 disciplines (prestige). Equipped skin is saved to localStorage cogito-bg; applyBackground()/initBackground() render it.
Daily Review: review.html is a cross-course spaced-repetition queue. review-cards.js (generated by scripts/gen-review.js from every course's CARDS array — rerun it if card text changes) holds the card content; scheduling stays in each course's own localStorage save. A course only contributes cards once its full initial pass is done in-course (every card lastReviewed != null). Ratings write back to each course using the same SM-2 logic, so progress syncs both ways.
Dev Tools (REMOVE BEFORE LAUNCH): dashed-red buttons in index.html below the course grid. "Set Global Lvl 75" injects XP into PRIMA. "Master All (80%)" writes high-interval cards to every course so all 7 disciplines hit ~100% maturity (unlocks mastery achievements + the Singularity skin). "30-Day Streak" writes 30 consecutive days to cogito-activity (unlocks streak achievements + Sonar skin + Emerald theme). "Reset All" runs localStorage.clear() then reloads, wiping ALL progress, streaks, unlocks, theme, and background back to zero (confirm()-guarded).
Syntax Rules: NEVER use backticks (`) inside JavaScript strings. Use single quotes and string concatenation (+) to avoid fatal parsing errors. This also applies to any line injected into a course page by a script: four pages (vonbertalanffy, godel, lakoff, wiener) have their JS minified onto a single line, so a `//` comment inserted there swallows the rest of the line and takes the whole course down. Use `/* */` or no comment.

Checks (run before committing; none of them need a browser)
  node scripts/check-contrast.js        WCAG contrast for all 8 themes. Fails under 4.5:1. Over 13:1 is reported as a comfort note, not a failure: Matrix green and cyberpunk yellow are the signature of two opt-in themes.
  node scripts/test-arena-nav.js        Next-Problem logic against the real ARENA of all 52 courses. Expectations written first.
  node scripts/check-arena-tell.js      The Arena answer-length scoreboard. Add --course x.html for one file, --simulate to test a proposed fix before writing content. Never fails the build.
  node scripts/rollout-arena-nav.js     Idempotent; reports before it writes. Run after adding a 53rd course.

Open work: the Arena answer-length tell. A guesser who always clicks the longest option is right 83% of the time across 2,358 questions, against 25% by chance; correct options average 58.7 characters and distractors 21.0. The rule for fixing it is NOT "write longer distractors". That was simulated and buys exactly nothing, because the tell is being the MAXIMUM, not the ratio: if the answer is still the longest, the guesser still wins. The rule is that **length must carry no information**, which means a distractor has to be the longest option roughly as often as the answer is. 81% of questions have no distractor within 90% of the correct option's length and need new text rather than editing. Distractors must also be genuinely plausible, which is a rule this file already had and the content does not honour. Where a correct option carries its own reason inline ("X, because Y"), move the reason into the explanation field, which 99.5% of questions already have. Do it one course at a time and re-run the scoreboard after each; cobra.html is the pilot (20 questions, currently 100%). Target is to walk each course down toward 25%.
